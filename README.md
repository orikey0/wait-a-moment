# 等一下（Wait a Moment）

访问容易分心的网站时，先等一等，再做选择。

扩展会在你打开被规则控制的网站时显示拦截页：倒计时结束前不能放行；可以选择「本次不浏览」，也可以在等待后选择临时放行 1 / 2 / 5 / 10 分钟。等待期间可以顺便复习几个单词。所有数据只保存在本机浏览器里，不需要账号，也不会上传。

- 技术：Chrome Extension Manifest V3，TypeScript（严格模式）
- 状态：第一版（0.1.0）。自动化测试全部通过，仍有一部分手动测试未执行，详见 [测试报告](docs/TEST_REPORT.md)。
- 许可证：MIT（默认选择，待项目所有者确认，见 [LICENSE](LICENSE)）

## 快速开始

需要 Node.js 20 或更新版本。

```bash
npm ci            # 按 package-lock.json 安装依赖
npm run build     # 生成 dist/ 目录，即可加载的扩展
```

在 Chrome 中加载：打开 `chrome://extensions`，开启「开发者模式」，点击「加载已解压的扩展程序」，选择项目里的 `dist/` 目录。

首次安装会预置四个示例网站（zhihu.com、tophub.today、x.com、v2ex.com），默认包含子域名，可在设置页编辑、停用或删除。

## 功能说明

| 功能       | 行为                                                                                                                                                                                              |
| ---------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 网站规则   | 支持整个域名（默认包含子域名）或某个路径（例如 `zhihu.com/hot`，只匹配 `/hot` 及其子路径，不匹配 `/hotel`）。输入会被规范化；拒绝非 http(s) 协议、非法域名和重复规则。不支持正则表达式。          |
| 等待       | 默认 10 秒，可设 0–120 秒。0 秒表示不强制等待，但仍显示选择界面。倒计时基于时间戳，后台标签页和刷新页面都不会重置或绕过等待。                                                                     |
| 本次不浏览 | 不进入目标网站。返回同一标签页中最近一次未受规则控制的页面；如果没有，显示扩展自带的完成页。不会关闭标签页。                                                                                      |
| 等待后浏览 | 等待结束后出现放行时长选项（默认 1、2、5、10 分钟，可在设置中修改）。放行以规则为单位，同一规则下的所有标签页共享截止时间；到期后再次访问会重新拦截。到期不会打断已经打开的页面。                 |
| 按钮移动   | 「等待后浏览」在鼠标靠近时会跳到播放区域内的另一个位置，降低惯性点击。按下鼠标或键盘聚焦时不会移动；「本次不浏览」始终固定。可在设置中关闭，或在系统开启「减少动态效果」时自动关闭。              |
| 单词学习   | 每次展示 4 个单词，可标记「认识」「不认识」「需要复习」。到期的复习词优先，其次是新词，最近展示过的词会被轮换。这是一个简单的间隔复习调度，不保证记忆效果。可在拦截页关闭，也可在设置中整体停用。 |
| 词表导入   | UTF-8 编码的 CSV，第一行必须包含 `word` 和 `meaning` 两列，最多 5000 行，单词不超过 60 字符，释义不超过 200 字符。任何一行出错，整个文件都不导入；与已有词条重复的单词保留原有进度。              |
| 统计       | 记录拦截次数、放弃次数、放行次数、放弃比例、授权时长、单词学习次数。支持今日、近 7 天、近 30 天，按网站查看，最近 7 天趋势，导出 CSV 或 JSON，关闭统计后不再采集。                                |
| 数据       | 导出全部数据（JSON）、导入备份、清除统计与单词进度、清除全部本地数据。所有破坏性操作都需要二次确认。                                                                                              |
| 暂停       | 设置页的「暂停所有拦截」开关，立即生效，规则和统计保持不变。                                                                                                                                      |
| 外观       | 跟随系统、浅色或深色。                                                                                                                                                                            |

### 指标定义

- 放弃比例 = 放弃次数 ÷（放弃次数 + 放行次数）。只统计有明确结果的拦截。
- 授权时长是你选择的放行时长，不等于实际浏览时长。
- 放弃浏览并不代表永久避免访问。

### CSV 词表示例

```csv
word,meaning
abandon,放弃；抛弃
achieve,实现；达到
```

## 权限与隐私

### 申请的权限

| 权限            | 用途                                                                                                     |
| --------------- | -------------------------------------------------------------------------------------------------------- |
| `storage`       | 在本机保存规则、设置、单词进度、统计和放行记录。拦截记录和标签页状态保存在会话存储中，浏览器重启后清除。 |
| `webNavigation` | 监听主框架的导航、重定向落地和单页应用的路由变化，判断是否需要拦截。子框架不会触发拦截。                 |

### 没有申请的权限

扩展没有申请 `tabs`、`scripting`、`alarms`，也没有申请任何网站访问权限（`host_permissions`），不注入内容脚本，因此不会读取网页正文或表单内容。跳转到拦截页使用 `tabs.update`，这个调用不需要额外权限，端到端测试已验证。单元测试会检查清单中的权限列表，防止以后误加权限。

### 隐私

- 没有账号、没有服务器、没有第三方统计或分析 SDK、没有远程代码。
- 扩展不会上传任何浏览记录、单词数据或操作数据。
- 日志只输出错误名称，不输出 URL 或页面内容。
- 默认不在无痕窗口中运行（manifest 未声明 `incognito`）。

## 架构与选型

| 方面       | 选择                                                               | 理由                                                                                             |
| ---------- | ------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------ |
| 语言       | TypeScript 严格模式，启用 `noUncheckedIndexedAccess`               | 对索引访问和可选值更严格                                                                         |
| 构建       | esbuild，直接打包三个入口（Service Worker、拦截页、设置页）        | 产物是 MV3 要求的 ES 模块，构建快，依赖少                                                        |
| UI         | 原生 DOM，无框架                                                   | 界面只有三个页面，不需要 React 的运行时；所有用户文本通过 `textContent` 写入，不使用 `innerHTML` |
| 单元测试   | Node 内置 `node:test`，测试文件先用 esbuild 打包                   | 见下方说明                                                                                       |
| 端到端测试 | Playwright + 真实 Chromium，加载构建后的 `dist/`                   | 能验证跨标签页、重定向、Service Worker 的真实行为                                                |
| 静态检查   | typescript-eslint（strict type-checked）、Prettier、`tsc --noEmit` | 统一风格，尽早发现类型问题                                                                       |

**为什么没有用 Vitest**：本项目最初使用 Vitest。但当前 npm 10.9 在解析 Vitest 4.x 及以上版本的 peer 依赖时会崩溃（arborist 的已知问题），而且 4.1.10 及以下版本存在安全公告。因此单元测试改用 Node 内置的测试运行器，依赖更少，也没有这些问题。

### 代码结构

```
src/core/         纯逻辑，不访问浏览器 API：规则匹配、导航决策、等待与放行计时、
                  拦截记录、单词调度、CSV 校验、统计聚合、设置校验、版本迁移、
                  按钮位置、备份格式
src/background/   Service Worker：监听导航、访问存储（串行执行）、处理页面消息
src/ui/           拦截页与设置页（原生 DOM）
src/shared/       类型定义、消息协议、界面文案（集中管理，便于以后增加英文）
src/data/         内置示例词表（CSV）
public/           manifest、页面 HTML、样式、图标
tests/unit/       单元测试（102 个）
tests/e2e/        端到端测试（13 个，含延迟测量与截图）
docs/             测试报告
```

### 关键设计

- **存储**：持久数据（规则、设置、词表、统计、放行记录）放在 `chrome.storage.local`；拦截记录、标签页状态和最近的单词组放在 `chrome.storage.session`，浏览器重启后清除。
- **串行化**：所有读改写操作都经过同一个队列执行，多个标签页同时导航时不会互相覆盖计数。
- **放行作用域**：放行绑定在匹配的规则上。同一规则下的所有标签页共享截止时间；多条规则同时匹配同一页面时，任一规则有效即可放行。
- **时间**：全部使用时间戳，不累加定时器次数。系统时间被调回到等待开始之前时，等待会重新开始；被调回到放行开始之前时，放行视为无效。两种情况都不会造成永久锁定。
- **统计去重**：拦截次数在拦截页真正显示后计一次；放弃或放行每次拦截只计一次；单词标记每个单词在每次拦截中只计一次，刷新页面不会重复计数。
- **单页应用**：只有路径变化才重新检查，查询参数和锚点变化忽略。
- **版本策略**：存储数据带有整数 `schemaVersion`。旧版本数据会就地升级（迁移注册在 `src/core/migration.ts`）；无法识别或来自更新版本的数据不会被覆盖。备份文件使用同样的版本规则。

## 已知限制

1. **可以通过修改系统时间提前结束等待。** 纯本地扩展无法防止这一点。系统时间被回拨不会导致永久锁定，但向前调整会缩短等待。
2. **扩展可以被用户禁用或卸载。** 扩展不做系统级强制。
3. **默认不在无痕窗口中生效。** 需要在 `chrome://extensions` 中手动允许。
4. **非 http(s) 页面无法拦截。** Chrome 内部页面、扩展商店页面、`file://` 等都会被跳过。
5. **后退/前进缓存（bfcache）恢复页面时是否会触发拦截，尚未在真实浏览器中验证。**
6. **单词学习的调度是启发式的**，不保证记忆效果。
7. **性能只做了导航延迟的测量**，没有做内存、CPU 和 Service Worker 唤醒耗时的分析。延迟测量包含测试驱动的开销。
8. **词表只支持 UTF-8 编码的 CSV。**

## 开发

```bash
npm run check        # 类型检查 + ESLint + 格式检查 + 单元测试 + 构建
npm test             # 只跑单元测试
npm run test:e2e     # 构建后运行 Playwright 端到端测试
npm run icons        # 重新生成工具栏图标
npm run format       # 统一格式化
```

端到端测试首次运行前需要安装浏览器：`npx playwright install chromium`。测试会把截图写入 `test-results/screenshots/`，该目录不纳入版本管理。
