## 4. 性能（AC-010 要求的实测）

**方法**：Playwright 在同一个浏览器中交替访问普通页面和受控页面，共 10 轮。普通页面计时从 `goto` 开始到页面 load 结束；受控页面计时从 `goto` 开始到拦截页的 `#gate` 出现。

| 运行       | 普通页面中位数 | 受控页面中位数 | 额外耗时中位数 |
| ---------- | -------------- | -------------- | -------------- |
| 第一次运行 | 18 ms          | 84.5 ms        | 66.5 ms        |
| 最终运行   | 18.5 ms        | 77 ms          | 58.5 ms        |

最后一次完整运行（加入备忘录之后）：普通页面中位数 14 ms，受控页面中位数 73 ms，额外耗时中位数 59 ms。

**局限**：这些数字使用 Playwright 的计时，包含测试驱动的开销，不等同于 DevTools 的精确测量。未测量内存占用、CPU 占用、Service Worker 的休眠与唤醒耗时，也没有测试大量标签页的场景。

## 5. 设计与界面检查

- **柱状图配色**：使用 dataviz 技能提供的校验脚本检查单色柱子。亮色底 `#fcfcfb` 上的 `#2a78d6`，以及暗色底 `#1a1a19` 上的 `#3987e5`，两者都通过了明度范围和对比度（≥ 3:1）检查。
- **截图检查**：生成了设置页（亮色、暗色，含 7 天数据）和拦截页（亮色、暗色）的截图，目视检查了布局、对比度和溢出情况。备忘录加入拦截页后，又重新截图检查了亮色拦截页：标题、说明、完成计数、输入框和折叠的「昨天」行都正常显示。截图写入 `test-results/screenshots/`，不纳入版本管理。
- **对比度**：界面颜色取自校验过的色板，正文与背景的对比度按 WCAG AA 的 4.5:1 设计。未使用自动化工具逐一测量。

## 7. 测试期间发现并修复的问题

| 问题                                                                            | 处理                                                  | 验证                                 |
| ------------------------------------------------------------------------------- | ----------------------------------------------------- | ------------------------------------ |
| 拦截页在「不可用」状态下，提示文字被包在 `#gate` 里，`#gate` 隐藏时提示也被隐藏 | 把提示移到 `#gate` 之外，做成独立卡片                 | 端到端测试「规则在浏览器重启后保留」 |
| 单词卡片没有标记时，状态行仍占一行空白                                          | 空状态行不再显示（`:empty`）                          | 截图检查                             |
| 测试辅助函数在导航被扩展中止时抛出 `ERR_ABORTED`                                | 改为轮询 URL 的断言（测试代码的问题，不是扩展的问题） | 端到端测试全部通过                   |
| 重启测试错误地使用了新的 profile 目录（测试代码的问题）                         | 改为复用同一个 profile 目录                           | 同上                                 |

备忘录功能加入后，测试中还出现过一个选择器问题：`getByLabel('写周报')` 同时匹配了复选框和删除按钮的 `aria-label`（「删除：写周报」），已改为精确匹配。这是测试代码的问题，不是产品缺陷。
